# Orientação de produto — Fogo de Conselho

> Ember é **plataforma de comunidades**. Este doc descreve o **primeiro ritual piloto** (Fogo de Conselho). A apresentação em `mockup/fogo-de-conselho-apresentacao.html` usa narrativa de uma comunidade específica — **não** amarra o produto a esse público ou vocabulário ("guerreiros", etc.).

## Tese

Não queremos criar uma nova comunidade. **Queremos cuidar da que já existe.**

Depois do GSA, a vida volta a acontecer em países, fusos, gerações e caminhos diferentes. O pertencimento pode continuar vivo. O encontro, nem sempre.

Não falta gente interessante. Não falta rede. Não falta vontade. **Falta espaço para o encontro acontecer.**

## O ritual

Pequeno o bastante para caber na vida. Significativo o bastante para manter um fio vivo.

| Elemento | Significado |
| -------- | ----------- |
| **3 GSAs** | Uma roda pequena. Espaço real de fala, escuta e presença. |
| **1 pergunta** | Um centro comum para iniciar. Não uma pauta a cumprir. |
| **30 minutos** | Tempo protegido. Sem entrega. Sem necessidade de produzir nada. |

## O que não é

- Não é networking
- Não é mentoria
- Não é reunião
- Não é mais um grupo

É um pequeno ritual de presença entre pessoas que já compartilham uma história de pertencimento.

## Como acontece (fluxo do membro)

1. **Escolhe horários** — poucos horários fixos por rodada; marca um ou mais.
2. **Declara intenção** — ex.: *me surpreenda*, *quero atravessar uma fronteira*, *quero facilidade*.
3. **A rede forma a roda** — idioma, fuso, histórico e diversidade trabalham silenciosamente.
4. **Você chega** — um clique para entrar; um clique para levar ao calendário.

## Sorteio com memória

Não para encontrar o trio "perfeito". Para criar pontes que ainda não existem.

| Critério | Peso |
| -------- | ---- |
| Horário em comum | essencial |
| Idioma em comum | essencial |
| Novos encontros | prioridade |
| Gerações diferentes | ponte |
| Geografias diferentes | ponte |

## Princípio de experiência

**A tecnologia desaparece.** Para quem participa, não existe "matching", infraestrutura ou configuração. Existe um convite.

### Poucos toques, poucas permissões, nenhuma burocracia

| Peça | Papel |
| ---- | ----- |
| WhatsApp | Abre a porta e carrega o convite da rodada (MVP 2) |
| Magic link | Reconhece sem senha e sem sensação de "criar conta" |
| Fuso local | A pessoa nunca faz conta de horário |
| Jitsi | Um link de conversa, sem conta para participar |
| `.ics` | Vai para o calendário sem entregar a agenda inteira |

## O que realmente cresce

Uma conversa entre três pessoas pode criar **três novos pares relacionais**. Ao longo do tempo, a memória da rede revela vazios, repetições e pontes ainda não feitas.

> Não queremos maximizar matches. Queremos aumentar os fios da rede.

## Primeira versão

A primeira versão só precisa ser boa o bastante para a primeira roda acontecer:

Rodada · horários fixos · sorteio com memória · link da conversa · calendário · confirmação.

Nada de feed, chat, perfis ricos, gamificação ou mais uma plataforma para manter.

## Hipóteses a validar

Ver também `roadmap.md` § Hipóteses. Da apresentação:

- Três pessoas é o tamanho certo?
- 30 minutos é suficiente?
- Quinzenal ou mensal?

- Quais pontes a rede quer atravessar?
- O que faz alguém querer voltar para a próxima roda?
